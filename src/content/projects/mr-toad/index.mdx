## Overview

Mr Toad is a rover built for robust navigation, using GPS, lidar obstacle avoidance and a 16 MP front camera. It's my third project funded by the Invention Studio's Maker Grant program, and a chance to sharpen my **ROS 2 and controls** skills in a form factor I hadn't built before, after a run of UAV projects.

The model above is the final assembly — select a part to inspect it.

## Inspiration

The design is inspired by the iRobot FirstLook 110, a neat UGV made for emergency services to scout dangerous places. I found it while researching harsh-environment rovers for my robotics team. I liked how compact and durable it was — small enough to throw, tough enough to survive the landing, and carrying a full sensor and comms package — so I set out to emulate some of those features.

### Climbing stilts

The first design tried to match the FirstLook's ability to climb tall obstacles, using servos placed co-axially with the front wheels. That meant I couldn't use a wheel shaft, so I designed a **bearing retainer** that constrains each wheel while letting it spin freely. Unfortunately, the servo horn was too small relative to the wheel opening for a structurally sound strut. I decided to finish the rover first and come back to the stilts in a future revision.

## Fabrication

The rover was too big for the printer's build plate, so the main shell parts had to be split in half. I could have designed in fastening points, but those would need extra outcroppings, so instead I **welded the plastic together with a soldering iron**, which leaves the seam visible in the photos below. For the plates, I embedded heat-set inserts into the top and bottom frames for the side plates to screw onto, which gives the whole thing a "tanky" look I enjoyed.

## Software: the OS problem

Communications, sensing and control ran into a pile of software conflicts that made development harder than it should have been. Mostly it came down to the OS: **Ubuntu or Raspberry Pi OS**.

I started with Ubuntu, for its great ROS 2 compatibility and community support. After writing the code for the sensors and drivers, I found the camera required software that didn't work on Ubuntu. After trying several workarounds, the path of least resistance was Raspberry Pi OS on the Pi. That meant no ROS 2 onboard without many other problems, so I structured the code so the ROS 2 processing, like obstacle avoidance, runs on the ground station instead.

Along the way I learned a lot more about:

- compiling from source
- ROS 2 on the Pi
- talking I²C to the LIDAR-Lite directly with `smbus`, instead of relying on prebuilt device packages

## Ground station

On the ground-station (laptop) side, I wanted to learn how to build a GUI for custom robotics:

- **PyQt5 interface:** receives the video stream over the network, along with the current lidar range.
- **Game-controller driving:** the built-in ROS 2 `joy` node feeds a custom UDP bridge, which turns the ROS controller messages into the UDP command stream the rover expects.
- **Camera stream:** the most interesting part, interfacing with it through OpenCV and GStreamer. That will carry straight into future unmanned vehicles that need to transmit video.
